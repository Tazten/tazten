一、产品是什么？

🎯 产品定位

无感记账是一款智能账单识别应用，用户只需上传账单图片，AI 会自动识别并记录每一笔消费，让记账变得简单无感。

💡 解决什么问题？

  • 传统记账需要手动输入金额、分类、时间等信息，操作繁琐
  • 消费后容易忘记记录，导致账目不完整
  • 用户不知道如何正确分类消费

我们的解决方案：拍照上传 → AI 自动识别 → 自动分类 → 自动保存，整个过程只需几秒钟。

三、整个开发流程是怎样的？

第一步：产品设计

在开始写代码之前，我先想清楚了产品要解决什么问题、用户如何使用、需要哪些功能。这就像盖房子前先画图纸一样重要。

第二步：搭建项目框架

使用 Cursor AI 帮助我创建 Next.js 项目，设置好基本的文件结构和配置。这就像搭好了房子的框架。

第三步：连接数据库（Supabase）

做了什么：

  • 在 Supabase 官网创建了一个项目
  • 创建了数据库表（用来存储交易记录）
  • 创建了存储桶（用来存放上传的图片）
  • 获取了 API 密钥，配置到项目中

为什么需要：产品需要保存数据，就像手机需要存储空间一样，Supabase 就是我的"云存储"。

第四步：对接 AI 识别服务（豆包 API）

做了什么：

  • 在火山引擎控制台开通了豆包视觉理解服务
  • 获取了 API 密钥和模型端点
  • 编写代码调用 API，把图片发送给 AI
  • 解析 AI 返回的结果，提取账单信息

为什么需要：这是产品的核心功能，AI 负责"看懂"账单图片，提取关键信息。

第五步：开发前端界面

做了什么：

  • 使用 Cursor AI 帮助编写 React 组件
  • 创建了上传页面（用户可以上传图片）
  • 创建了历史记录页面（用户可以查看所有记录）
  • 创建了详情页面（用户可以查看单条记录的详细信息）
  • 设计了美观的界面，使用了渐变、卡片等现代设计元素

为什么需要：用户需要一个友好的界面来使用产品，就像手机需要屏幕一样。

第六步：开发后端逻辑

做了什么：

  • 创建了 API 接口，接收用户上传的图片
  • 编写代码把图片上传到 Supabase 存储
  • 调用豆包 API 识别图片内容
  • 验证识别结果，确保数据正确
  • 把识别结果保存到数据库

为什么需要：前端负责展示，后端负责处理业务逻辑，就像餐厅的前台和厨房一样。

第七步：测试和优化

做了什么：

  • 在本地测试所有功能是否正常
  • 修复发现的问题和错误
  • 优化用户体验（比如添加加载提示、错误提示）
  • 确保手机端也能正常使用

第八步：部署到公网（Vercel）

做了什么：

  • 把代码推送到 GitHub
  • 在 Vercel 中连接 GitHub 仓库
  • 配置环境变量（数据库密钥、API 密钥等）
  • Vercel 自动构建和部署
  • 获得公网访问地址

为什么需要：只有部署到公网，其他人才能访问你的产品。

四、用户如何使用产品？

🔄 完整使用流程

  1. 访问网站：用户在浏览器中打开产品地址
  2. 上传图片：点击或拖拽上传账单图片（支持 JPG、PNG 格式）
  3. AI 识别：系统自动调用 AI 识别图片内容（约 30 秒）
  4. 自动保存：识别结果自动保存到数据库
  5. 查看结果：用户可以查看历史记录，或点击查看详情

✨ 核心功能

功能 说明
📤 图片上传 支持点击上传或拖拽上传，自动验证文件格式和大小
🤖 AI 识别 自动识别账单中的金额、商户、分类、时间等信息
📋 历史记录 查看所有交易记录，支持按类型筛选（支出/收入）
🔍 详情查看 查看单条记录的完整信息，包括原始图片和识别结果
📊 数据统计 自动统计总记录数、总支出、总收入

五、技术实现概览

📁 项目结构（简化说明）

项目就像一本书，有不同的章节：

  • app/：存放页面和 API 接口（就像书的正文）
  • components/：存放可复用的组件（就像书的插图，可以在多处使用）
  • lib/：存放工具函数（就像书的附录，提供辅助功能）

🔄 数据流转过程

当用户上传一张图片时，数据是这样流动的：

  1. 用户上传 → 图片从用户的电脑发送到服务器
  2. 存储图片 → 服务器把图片保存到 Supabase 存储
  3. 调用 AI → 服务器把图片地址发送给豆包 API
  4. AI 识别 → 豆包 API 分析图片，返回识别结果
  5. 保存数据 → 服务器把识别结果保存到 Supabase 数据库
  6. 显示结果 → 前端从数据库读取数据，展示给用户

💡 关键理解：

整个产品就像一个"智能助手"：

  • 前端：负责和用户交互（就像助手的"脸"）
  • 后端：负责处理业务逻辑（就像助手的"大脑"）
  • 数据库：负责存储数据（就像助手的"记忆"）
  • AI 服务：负责识别图片（就像助手的"眼睛"）
